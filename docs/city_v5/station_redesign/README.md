# 晴岚中央车站：整体设计与 Tripo 构件包

这是一套新车站的设计参考：先确认整体，再逐件生成可复用构件，回收后统一整理尺寸和拼装。**目前尚未替换正式游戏中的车站或地图。**

## 先看整体，再选单件

- [整体四视图](boards/station_views.png)：整体透视、正面、右侧、俯视。
- [11类构件编号总览](boards/modules_overview.png)：模块形状、设计尺寸、实际包围盒和复用数量。
- [离线模块目录](模块目录.html)：逐件查看原始视图。
- [Tripo逐模块提示](Tripo逐模块提示.md)：对应模块的生成说明。

整体和模块视图均由同一套 Blender 设计模型切换相机渲染，保留一致的造型与组装关系。它们是设计参考，不是已经由 Tripo 生成的成品。

总览图带有文字、编号和多个构件，用于阅读与讨论。**上传 Tripo 时使用某一个模块文件夹中的 `hero.png` 原图，不上传整张总览。**

如果当前生成界面支持同一对象的多视图输入，再附上该模块的 `front.png`、`right.png`、`back.png`、`top.png` 辅助核对。若仅支持单图，就用 `hero.png`；其余视图用于人工检查和修模，避免把几个不同模块的图片当成同一对象输入。

## 建议顺序

先做 **M01、M02、M03、M04、M08**：中央到达大厅、翼楼标准开间、翼端亭楼、候车厅拱顶段、中央时钟冠饰。这5件确定站房的主要比例、材料和细节密度，确认后再做雨棚、后端拱窗、灯具及徽章。

每一类只需先生成一个干净模块，按设计清单复用；不要为了画面中的每个实例分别生成不同版本。11类外观模块不包含场地地形、轨道与站台等需要精确尺寸的基础骨架。

## 怎样理解尺寸

[manifest.json](manifest.json) 是模块信息来源，[assembly.json](assembly.json) 记录本设计的摆放关系。

- 尺寸顺序均为 **宽 × 高 × 深**，单位为米，对应 Godot 的 **X × Y × Z**；正面朝 `-Z`。
- `dimensions` 表示设计体量或名义模块尺寸；连接位置以该模块的 `interfaces` 说明为准。
- `actualDimensions` / `actualBounds` 是实际模型的外包围盒，包含檐口、门廊、栏杆、装饰外挑和基础等几何，因此可能比名义尺寸更大。
- 不要为了让含檐口包围盒等于名义尺寸而直接整体压缩模型；先核对主体与拼接面，再处理外挑件。

图像会分别取景以展示细节，画面里的像素大小不是各模块之间的统一比例尺。几何更新后，请以最新 manifest、组装数据和对应视图为准。

## M07 与 M09 的处理

**M07楼梯、M09台阶与缓坡建议最终用 Blender 精确重建。** 它们需要准确控制踏步、休息平台、上下楼面标高、净宽和可走碰撞。Tripo 可用于探索石材、栏杆等外观，但图生外观网格不能直接代替这些通行几何。

其余模块也需保留接口处的开口和通道。门洞、拱顶端面、柱间通路不能因为生成结果而被封成实体墙；后续组装后还要在游戏中验证实际行走与入口。

## 更新总览图

所有最终视图和 manifest 写完后，在项目目录运行：

```powershell
python tools/city_web/build-station-boards.py
```

脚本只读取清单和现有图片，输出 `boards/modules_overview.png` 与 `boards/station_views.png`。图片完整保留，不裁掉构件；若图片缺失或读取期间文件变化，则停止输出，避免用不完整的视图覆盖已有总览。可使用 `--modules-only` 或 `--views-only` 单独更新一张。
