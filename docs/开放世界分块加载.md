# 开放世界分块加载

适用于晨露谷和潮风高地。风语旧圣堂继续作为独立实例加载。正式地图、地形资源、建筑源资产和存档坐标版本均沿用原内容。

## 加载层次

| 层次 | 常驻内容 | 按位置创建、回收的内容 |
| --- | --- | --- |
| 世界 | 两个区域的数据壳、出生点、任务与探索标记、完整地图轮廓 | 不再进入世界时创建所有单位与建筑生成树 |
| 地形 | 高度/涂层数据、低分辨率远景、水面、外部远山 | 80 米地形格，240 米内详细网格和逐格高度场碰撞，340 米后回收 |
| 场景 | 建筑参数、森林点位、城市房屋布局 | 120 米空间分组；普通道具约 200 米，按尺寸扩大地标范围；加 100 米回收迟滞 |
| 城市 | 全城简模天际线 | 附近街区的完整模型和房屋碰撞，细节生成完才隐藏对应简模 |
| 森林 | 原始点位与稳定的变体索引 | 按 120 米分组生成 MultiMesh 和碰撞；树木保留较远可见范围 |
| 单位 | 刷新点、稳定槽位、刷新期限、休眠位置 | 150 米内生成 NPC/怪物/采集物，230 米外回收可安全休眠的单位 |

`WorldStream` 统一调度附近地形、建筑和单位。先准备附近地面，同时后台读取最多两个模型资源，逐项提交和释放，挂入场景树的工作按帧推进。正常移动每帧软预算 3 毫秒；单个引擎对象的实例化不能被预算强行切开，因此预算不等于单帧耗时保证。日志记录实际最长单项及对象名。

远景地形与近景不叠放，格边裙面封住高低网格的视觉缝隙；碰撞始终使用原始高度采样。森林拆分保留原索引，避免每次进出区块改变树木变体和朝向。世界地图仍从完整原始数据壳绘制，与当前区块驻留无关。

## 玩法状态与传送

- 战斗、受伤、光环、施法、当前目标、打开的 NPC 服务和尸体会保留。调度器同时保留其脚下静态内容；怪物返回出生点的路径也保留地形支撑。
- 怪物死亡后，尸体和掉落仍由原实例管理，刷新槽位另记期限。采集槽位同样保留冷却。离开、返回区块不会触发额外击杀奖励或提前补货。
- 刷新属于原区域，移除了使用玩家当前 `Game.zone` 的延迟刷新回调。更换世界时收完后台读取，然后销毁旧调度器和刷新槽位。
- 传送、炉石、飞行、列车、墓地均先准备目标附近地形、建筑和单位，再等待物理帧、移动玩家。过渡期间玩家和其他战斗单位一致暂停，宠物随主人移动。
- 正常移动若脚下碰撞尚未准备，暂缓移动而不是放任角色下落。通常附近预加载会在到达边界前完成。

## 创作与维护

仍编辑原始地图场景及生成器，无需维护一套分块地图副本。编辑器地形笔刷及副本保留原来的完整重建路径。

金穗镇建筑的 GLTF 合并与碰撞生成移到派生资源 `assets/streaming/goldshire/`。重建命令：

```powershell
& 'F:\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe' --headless --path E:/wowgame --audio-driver Dummy res://tools/bake_stream_assets.tscn
```

缓存绑定源 GLB 和构建脚本的 SHA-256。缺失或失效时走原资产构建流程，保持内容正确；重新生成缓存可恢复预处理收益。不要手动把旧缓存复制成新版本。

开发诊断可把 `Game.settings["world_streaming"]` 设为 `false`，比较完整加载路径；默认开启，不增加游戏界面选项。

## 验证入口

- `tests/check.tscn`：脚本加载检查。
- `tests/streaming.tscn`：真实世界里的分块驻留、接缝碰撞、连续移动、传送、掉落、采集刷新、请求中卸载、副本往返。
- `tests/streaming_lifecycle.tscn`：确保存在尚未收回的真实后台读取，再立即切换副本并返回，检查旧请求收尾及相同资源重载。
- `tests/autotest.tscn -- mode=basic` / `mode=services`：原有玩法与服务回归，已适配按 NPC 标记准备目标后再交互。
- 自动化角色统一使用 `slot_index = -1`，不写用户角色存档。

运行报告、版本清单与原始日志：`.local/streaming_20261006/`。截图：`.shots/streaming_20261006/`。改动前源文件备份：`.local/streaming_20261006/backup/`。

注意：旧巡游坐标 `(-1080, 632)` 位于当前城市住宅实体内；完整加载对照同样会把角色挤向地下。本轮落点回归改用地图正式的 `fp_solenne` 标记，保留旧失败与对照日志。没有通过改动地形或强行抬高玩家掩盖这一测试前提错误。

## 本机验证结果（2026-10-06）

Godot 4.7.2、Forward+、GTX 1650 Ti。正式候选 `streaming-final-v3`、证据 `streaming-final-e4`，清单 `.local/streaming_20261006/final_manifest.json` 记录文件指纹和各轮证据适用范围。

| --- | --- | --- |
| 世界主要构建阶段日志合计 | 25,989 + 15,626 = 41,615 ms | 3,468 + 2,934 = 6,402 ms |
| 初始完整单位数量 | 510 | 53 |
| 初始详细地形格 | 全图完整构建 | 31 / 769 |
| 初始静态生成树 | 全图构建 | 425 / 1,834 个描述项 |

分块测试从启动角色到加载完成共 9,805 ms；这个总时长包含不同阶段，不能直接与上表旧版 41,615 ms 相除。以上是本机样本，未控制操作系统文件缓存，也不是各配置下的固定速度保证。

- 分块集成回归 `run4`：56 项通过，0 失败。接缝步行 2,022 个位置采样未穿地；2,021 帧耗时样本 p95 = 15 ms、p99 = 24.49 ms、最大 76.99 ms。保留端点截图和数值结果，未做连续视频观感验收。
- 区块切换画面 `visual_clip`：另用真实移动输入跨区并返回，15.98 秒采集全部 242 个渲染帧，期间实际生成 13 个、回收 14 个静态描述项，详细地形格从 45 变为 49。保留时间戳、完整帧表及原时间间隔的 `boundary_return.mp4`；用于检查中间画面的技术连续性。采集限 15 FPS 且有截图开销，不参与性能比较，不代表已按正常速度观看并验收主观流畅度。
- 后台请求专项 `lifecycle_gpu`：5 项通过，0 失败。资源从实际读取中（状态 1）到旧世界卸载后请求已收回（状态 0），返回后相同资源加载完成。无界面首探存在 dummy 渲染器错误，最终以真实显卡专项为准。
- 基础流程到达 `AUTOTEST DONE`；服务回归 25 PASS / 0 FAIL，包括列车往返及副本进出。服务回归早于最后的后台读取并发限制和地形优先顺序调整，交互及传送语义未再改动。
- 最终脚本检查 110 / 0；3 份用户角色存档、3 个地图场景、地图生成器、世界布局与核心配置的已登记基线哈希不变。

尚有优化空间：复杂建筑的单项实例化仍可能突破软预算，独占显卡集成测试记录约 308–313 ms 的房屋尖峰，基础流程最长单项约 202 ms。专项与脚本加载检查重叠时曾记录 430 ms，该轮不用于性能比较。3 ms 是调度停止继续工作的阈值，不能切断正在执行的引擎调用。后续应针对这些建筑继续拆小生成步骤或预处理碰撞，再用同条件路线复测。
